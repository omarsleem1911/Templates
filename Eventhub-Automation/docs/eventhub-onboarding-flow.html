Phase 0 · One-time setup (before any customer)

Done once by cor., not per customer.

APP

cor. onboarding (PoC) app

Registered in cor.'s own tenant by python method2_setup.py register. Multi-tenant (AzureADMultipleOrgs), public client: no secret, no permissions of its own.

client ID 80c7f93c-2e46-477a-8488-faf0b4534974 · redirect URI http://localhost:8401/m2/callback

TEMPLATE

Public ARM template

Azure downloads the template itself at deployment and refuses localhost, so a copy is published on GitHub and set in eventhub/settings.json.

https://raw.githubusercontent.com/omarsleem1911/Templates/main/eventhub/azuredeploy.json

Phase 1 · Sign in and authorize

One interactive sign-in. The authorization code flow with PKCE, from a public client: no client secret exists anywhere.

1

Admin starts the onboarding

Admin's browser→cor. Hub

The admin chooses the options and clicks Sign in with Microsoft. The Hub creates the connection ID (16 random hex characters) and its record, makes a PKCE pair and a one-time state, and keeps the PKCE verifier in memory under that state.

POSThttp://localhost:8401/eh/start
Form fields
tenant (e.g. OmarKhwatoutlook.onmicrosoft.com; required for personal accounts), entra=1, activity, consent
Saved
state/eventhub-conn/<id>.json: id, createdAt, state signin, options
Response
302 to the Microsoft authorize URL (step 2)
2

Microsoft sign-in and consent

Admin's browser→Microsoft Entra ID

The admin picks the account and, the first time (or when Always show the consent screen is ticked), accepts the permissions for cor. onboarding (PoC). The first consent also adds the app to the customer tenant's Enterprise applications.

GEThttps://login.microsoftonline.com/{tenant}/oauth2/v2.0/authorize
Query
client_id, response_type=code, response_mode=query, redirect_uri=http://localhost:8401/m2/callback, state, code_challenge + code_challenge_method=S256, prompt=select_account (or consent)
Scopes
openid profile https://management.azure.com/user_impersonation. No offline_access, so no refresh token.
Response
302 back to /m2/callback?code=…&state=…
3

The Hub redeems the code for one access token

Admin's browser→cor. Hub→Microsoft Entra ID

The Hub checks state, then exchanges the code server-side. The token never reaches the browser.

GEThttp://localhost:8401/m2/callback?code=…&state=…
Then
Server-to-server token request below
POSThttps://login.microsoftonline.com/{tenant}/oauth2/v2.0/token
Body (form)
grant_type=authorization_code, client_id, code, redirect_uri, code_verifier, scope. No client secret.
Response used
access_token (ARM audience) and expires_in (about 60–90 min). Claims read: tid (tenant), upn (who signed in).
Kept
In memory only: SESSIONS[id] = {access, tenant, until}, until = sign-in + 60 min or token expiry − 2 min, whichever is first. The token response is wiped.
Saved
Record: state waiting, tenant, signedInAs, progress lines
4

The Hub starts the background watcher

cor. Hub

A background thread starts watching for this connection's deployment (phase 3). The browser lands on the Connecting your Event Hub page, which polls /eh/status every 4 seconds and reloads when progress changes.

Phase 2 · Deploy from the Azure portal

Done by the admin in the Azure portal, as the admin. cor. has no part in these requests beyond serving the form.

5

Admin opens Deploy to Azure

Admin's browser→Azure portal
OPENhttps://portal.azure.com/#create/Microsoft.Template/uri/{template URL}/createUIDefinitionUri/{form URL}
Template URL
The GitHub raw URL (static, same for every customer)
Form URL
http://localhost:8401/eh/createUiDefinition.json?id={connection ID} (per connection)
6

The portal loads the template and cor.'s form

Azure portal (in the browser)→GitHubcor. Hub
GEThttps://raw.githubusercontent.com/omarsleem1911/Templates/main/eventhub/azuredeploy.json
Returns
The ARM template: 13 parameters, 6 resources, no secrets in outputs
GEThttp://localhost:8401/eh/createUiDefinition.json?id={connection ID}
Returns
The form, with the connection ID as a fixed output (corConnectionId) and a link back to the Hub page. Sent with Access-Control-Allow-Origin: * so the portal can read it.
7

The form checks the names are free

Azure portal→Azure Resource Manager

Runs as the admin while they type (the form's ArmApiControl elements).

POST/subscriptions/{sub}/providers/Microsoft.EventHub/checkNameAvailability?api-version=2024-01-01
Body
{"name": "<namespace>"} → nameAvailable, message
POST/subscriptions/{sub}/providers/Microsoft.Storage/checkNameAvailability?api-version=2023-05-01
Body
{"name": "<account>", "type": "Microsoft.Storage/storageAccounts"}
8

Review + create, then Create

Azure portal→Azure Resource Manager→GitHub

The portal validates, then submits the deployment. ARM downloads the template from the link itself, which is why it must be public HTTPS.

PUT/subscriptions/{sub}/resourcegroups/{rg}/providers/Microsoft.Resources/deployments/{CustomDeployment-…}
Body
templateLink.uri = GitHub URL; parameters = form values, including corConnectionId
Parameters
location, namespaceName, eventHubName (coreventhub), pricingTier (Basic), throughputUnits (1), partitionCount (2), retentionHours (24), sharedAccessPolicyName (corehSAS), consumerGroup ($Default), storageAccountName, containerName (corcontainer), storageKeyExpirationDays (365), corConnectionId
9

ARM creates the resources

Azure Resource Manager
ResourceAPI versionSettings
Microsoft.EventHub/namespaces2024-01-01Basic tier, 1 TU, TLS 1.2. Tags cor-integration=eventhub, cor-connection-id=<id>
…/namespaces/eventhubs2024-01-012 partitions, cleanup Delete, 24 h retention
…/namespaces/authorizationRules2024-01-01corehSAS: Manage, Send, Listen
…/eventhubs/consumergroups2024-01-01Only if a name other than $Default is given
Microsoft.Storage/storageAccounts2023-05-01StorageV2, Standard LRS, TLS 1.2, no public blob access, key expiration policy 365 days. Same tags
…/blobServices/default/containers2023-05-01corcontainer, private

Outputs: names only (namespace, event hub, consumer group, policy name, rule ID, storage account, container). No connection strings, so none in Azure's deployment history.

10

Portal shows "Your deployment is complete"

Azure portal

Azure cannot redirect anywhere after a deployment. The admin returns to the Hub tab (the form carried a link to it); its title turns to ✓ Event Hub connected once phase 5 finishes.

Phase 3 · cor. watches for the deployment

The background watcher, as the admin, with the single access token. Repeats every 15 seconds until the deployment succeeds, fails, or the sign-in's time runs out. Temporary failures (dropped connection, timeout, 408, 429, 5xx) are retried 4 times with 2, 4, 8 s backoff.

11

List the subscriptions the admin can see

cor. Hub→Azure Resource Manager
GEThttps://management.azure.com/subscriptions?api-version=2022-12-01
Header
Authorization: Bearer <admin access token>
Used
Subscriptions with state = Enabled
12

Find this connection's resources by tag

cor. Hub→Azure Resource Manager

This is what the connection ID is for: cor. never asks which subscription or resource group the admin chose.

GET/subscriptions/{sub}/resources?$filter=tagName eq 'cor-connection-id' and tagValue eq '{id}'&api-version=2021-04-01
Used
The Microsoft.EventHub/namespaces and Microsoft.Storage/storageAccounts entries; the resource group comes from the namespace ID
13

Check the deployment's state

cor. Hub→Azure Resource Manager
GET/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Resources/deployments?api-version=2021-04-01
Match
The newest deployment whose parameters.corConnectionId equals this connection ID
Decision
Succeeded → phase 4 · Running/Accepted → keep watching · Failed/Canceled → stop and report
Used
Outputs: eventHubName, sharedAccessKeyName, containerName, consumerGroup

Phase 4 · Retrieve the strings and configure logging

Still as the admin, once, right after the deployment succeeds.

14

Get the Event Hub connection string

cor. Hub→Azure Resource Manager
POST{namespace ID}/authorizationRules/corehSAS/listKeys?api-version=2024-01-01
Used
primaryConnectionString: Endpoint=sb://<ns>.servicebus.windows.net/;SharedAccessKeyName=corehSAS;SharedAccessKey=…
Needs
The admin's Microsoft.EventHub/namespaces/authorizationRules/listKeys/action (Owner or Contributor)
15

Get the storage key and its expiry

cor. Hub→Azure Resource Manager
POST{storage account ID}/listKeys?api-version=2023-05-01
Used
keys[0].value (key1) and keys[0].creationTime. cor. builds DefaultEndpointsProtocol=https;AccountName=…;AccountKey=…;EndpointSuffix=core.windows.net
GET{storage account ID}?api-version=2023-05-01
Used
properties.keyPolicy.keyExpirationPeriodInDays → expiry = creation + period (e.g. 2027-11-10). Event Hub SAS keys have no expiry.
16

Read the hub's shape

cor. Hub→Azure Resource Manager
GET{namespace ID}/eventhubs/{eventhub}?api-version=2024-01-01
Used
partitionCount, retentionDescription.retentionTimeInHours; the tier comes from the namespace's sku
Saved
Record: names, region, subscription, both connection strings (PoC), expiry, hub details, state collecting

cor. Hub→Azure Resource Manager

The automated PDF step 9. Needs Global Administrator or Security Administrator; without it the page says so and the rest still completes.

  "eventHubAuthorizationRuleId": "{namespace ID}/authorizationRules/corehSAS",
  "eventHubName": "coreventhub",
  "logs": [{"category": "AuditLogs", "enabled": true}, … 19 categories]}}

AuditLogs, SignInLogs, NonInteractiveUserSignInLogs, ServicePrincipalSignInLogs, ManagedIdentitySignInLogs, ProvisioningLogs, ADFSSignInLogs, RiskyUsers, UserRiskEvents, NetworkAccessTrafficLogs, RiskyServicePrincipals, ServicePrincipalRiskEvents, EnrichedOffice365AuditLogs, MicrosoftGraphActivityLogs, RemoteNetworkHealthLogs, NetworkAccessAlerts, NetworkAccessConnectionEvents, AzureADGraphActivityLogs, MicrosoftServicePrincipalSignInLogs

18

Optional: stream every subscription's activity log

cor. Hub→Azure Resource Manager

Only when Also stream the activity log was ticked. The automated version of the PDF's az loop.

PUT/subscriptions/{sub}/providers/Microsoft.Insights/diagnosticSettings/corlogging?api-version=2021-05-01-preview
Body
Same rule ID and hub; categories Administrative, Security, Alert, Recommendation, Policy. Once per enabled subscription.

Phase 5 · Discard the sign-in, test, finish

19

Discard the admin's token

cor. Hub

The in-memory session is cleared and removed. No refresh token was ever issued, so cor. can no longer act as the admin. The record notes signInDiscardedAt and signInDiscardedReason.

20

Test the Event Hub connection string

cor. Hub→Event Hubs

Uses only the connection string, as the connector will. No Azure sign-in involved.

GEThttps://{namespace}.servicebus.windows.net/{eventhub}?api-version=2014-01&timeout=60
Header
Authorization: SharedAccessSignature sr={url-encoded resource}&sig={HMAC-SHA256 with the policy key}&se={now + 5 min}&skn=corehSAS
Pass
200 with the hub description (partition count read from it)
21

Test the storage connection string

cor. Hub→Blob Storage
GEThttps://{account}.blob.core.windows.net/{container}?restype=container
Headers
x-ms-date, x-ms-version: 2021-08-06, Authorization: SharedKey {account}:{HMAC-SHA256 of the canonical request with the account key}
Pass
200 with the container's properties
Saved
Record: test (ok, time, per-check detail), state done
22

The Hub page shows the result

Admin's browser→cor. Hub
GEThttp://localhost:8401/eh/status?id={id}
Every
4 seconds while the onboarding runs
Returns
{state, updatedAt, steps}. Never a secret.
Then
The page reloads into the result: Azure resources, connector credentials (masked, Show), expiry, connection test, log streaming, timeline

Phase 6 · After onboarding

TEST

Test connection

POST /eh/test re-runs steps 20 and 21 with the saved strings. Needs no sign-in.

RESUME

Sign in again and continue

POST /eh/resume repeats phase 1 for the same connection ID, for an onboarding whose sign-in expired or was lost on a restart.

CANCEL

Cancel and discard the sign-in

POST /eh/cancel stops the watcher and discards the token at once. State cancelled.

DELETE

Delete / Delete all

POST /eh/delete and /eh/delete-all discard any live sign-in, then delete cor.'s record. Azure resources are not touched.
